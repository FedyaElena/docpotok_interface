# Интерактивный прототип ДокПоток

Прототип по макетам Figma (экраны 01–05, 06 и 08 в версии от 15.10). Работает без установки и сервера: откройте `index.html` в Chrome. Любые email и пароль подходят.

## Как это работает

1. Респондент заходит, нажимает «Загрузить счет» (или перетаскивает файл в очередь).
2. Прототип узнает документ по **имени файла** и показывает для него свои поля и свою таблицу разноски.
3. Файл `doc1.pdf` дает результат документа 1, `doc2.pdf` – документа 2 и так далее до `doc12`. Подходят и такие варианты: `doc_3.pdf`, `Doc 07.png`. `doc1` не путается с `doc10`.
4. Файл с любым другим именем даст ошибку «Не удалось распознать документ» (так респондент увидит сценарий ошибки).
5. Таблица разноски редактируется: ячейки, добавление и удаление строк, итог пересчитывается. «Подтвердить и создать проводки» формирует Excel, который можно скачать.

В очереди остальные строки (ИП Сорокин, Феникс Лог и т.д.) статичные, как в макете. Открывается только счет МорТранс и загруженные респондентом документы.

## Что в папке

| Путь | Что это |
|---|---|
| `index.html`, `css/`, `js/` | сам прототип |
| `js/config.js` | настройки: время «обработки», адрес для журнала |
| `data/docs.js` | данные 12 документов (создается скриптом, руками не править) |
| `data/source/doc1.xlsx … doc12.xlsx` | исходные Excel с результатами разноски |
| `tools/build_docs.py` | собирает `data/docs.js` из Excel |
| `test-files/doc1.pdf … doc12.pdf` | временные счета для проверки |

## Подставить свои данные (следующий этап)

1. Положите свои Excel в `data/source/` под именами `doc1.xlsx … doc12.xlsx` (заменив демо).
2. Один раз: `pip install openpyxl`.
3. Запустите `python tools/build_docs.py` – обновится `data/docs.js`.

Формат Excel (образец – любой демо-файл):
- лист **«Разноска»**: колонки `Дата, Счет Дт, Счет Кт, Поставщик, Валюта, Сумма, Перевозка, Плательщик, Номер документа, Описание расхода, База распределения`, каждая проводка – строка;
- лист **«Счет»** (необязательный): пары «Поле – Значение» (Поставщик, ИНН, Номер счета, Дата, Сумма без НДС, Ставка НДС, Сумма НДС, Итого, Валюта и др.). Если листа нет, значения посчитаются из проводок.

Если настоящие счета называются не `doc7.pdf`, а иначе, впишите имя файла в лист «Счет» в поле **«Имя файла»** (несколько имен через `;`), и прототип будет узнавать именно их.

## Журнал действий для оценки удобства

Записывается автоматически: клики (в том числе мимо элементов), экраны, загрузки, правки ячеек, добавление и удаление строк, подтверждение, время.

- **Панель исследователя**: `Ctrl + Shift + L`. Там код участника, сводка (время от загрузки до подтверждения, число кликов и правок), кнопки «Скачать журнал CSV» и «Новая сессия».
- Код участника можно задать прямо в ссылке: `…/index.html?p=R01`.
- Журнал хранится в браузере того, кто проходит тест. Если вы рядом (встреча, демонстрация экрана), скачайте CSV сами в конце. Если респонденты проходят без вас, нужно подключить отправку на сервер (`logEndpoint` в `js/config.js`) – это отдельный небольшой шаг.

## Публикация на GitHub Pages

1. Создайте отдельный репозиторий (лендинг на dokpotok.tech лучше не трогать) и загрузите в него содержимое этой папки.
2. Settings → Pages → Branch: `main`, папка `/ (root)`.
3. Ссылка будет вида `https://<логин>.github.io/<репозиторий>/`. Для респондента добавляйте `?p=R01`.
4. Положите респонденту папку `test-files` с 12 файлами (или ваши настоящие счета с нужными именами).

## Отличия от макета

- «ё» заменена на «е», длинное тире на среднее (по вашим правилам для текстов).
- Добавлено состояние «Обработка…» после загрузки (по умолчанию 2,6 секунды, меняется в `config.js`) и состояние ошибки для нераспознанного файла.
- После подтверждения таблица блокируется, чтобы респондент видел результат.
